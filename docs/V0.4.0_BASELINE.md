## Known Limitations (v0.3.0)

1. **No dataset semantics** — any DataFrame accepted by any analysis, including temporal methods on unordered data
2. **No applicability registry** — all detectors run regardless of dataset structure
3. **Limited evidence taxonomy** — only anomaly/no-anomaly, NOT_APPLICABLE not represented
4. **Comparison is mean-based** — no bootstrap, no confidence intervals, no effect size
5. **No equivalence testing** — TOST not implemented; non-significance ≠ equivalence
6. **Change-point on unordered data** — not explicitly rejected; runs on any numeric series
7. **No paired/unpaired distinction** — comparison doesn't track pairing
8. **No detector consensus** — no mechanism to combine evidence across detectors
9. **No evaluation mode** — no ground-truth comparison with PR/ROC metrics
10. **No schema versioning** — no `schema_version` field in outputs
11. **No reproducibility metadata** — no package versions, random seed tracking, input SHA
12. **Modified Z-score exists but not documented as robust univariate evidence** — 0.6745 scaling present
13. **No detector family diversity tracking** — three tree-based methods not identifiable as correlated

## Incompatibilities Introduced by v0.4.0

1. **DetectionResult.scores** — currently `tuple[float | None, ...]`, may add `percentile` normalization
2. **ComparisonResult** — currently has `status`, adding new statuses: IMPROVEMENT_SUPPORTED, EQUIVALENT_WITHIN_MARGIN, DIFFERENCE_DETECTED_DIRECTION_UNCLEAR, INSUFFICIENT_POWER, INCONCLUSIVE
3. **ChangePointResult** — new applicability check may return NOT_APPLICABLE instead of empty candidates
4. **CLI exit codes** — currently 0/1/2, new phases add no new exit codes but new result types affect `--fail-on`
5. **New CLI commands**: `inspect`, `detect`, `evaluate`, `consensus`, `validate`

Backwards compatibility goal: **v0.4.0 maintains full CLI/API backwards compatibility** for all existing commands. New result fields are additive only.
